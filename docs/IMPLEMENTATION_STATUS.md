# Implementation status

## Starter code built

- Modular FastAPI application with application factory, settings, request IDs, health/readiness routes.
- Workbook importer and normalized catalog snapshots with source workbook/sheet/row provenance.
- SQLite schema for catalogs, observations, profiles, schedules, audits, memory, proposals and video metadata.
- Typed domain contracts for observations, provenance, statuses, confidence, metric results, assistant responses and schedule events.
- Observation ingestion with canonical unit conversion for the currently supported metric set, UTC timestamp storage, metric-variant validation for HRV, duplicate rejection and explicit source-conflict flags.
- Metric service with safe missing-data statuses, clearly labeled raw-median prototype aggregation, and baselines requiring minimum sample and distinct valid-day counts.
- Tests for unit conversion, timestamp normalization, duplicates, HRV variant separation, source conflicts and baseline day coverage.
- Workout query and a separate safety-validation service; automated coach draft blocks unreviewed exercises.
- Coach draft endpoint; no plan is committed directly.
- Schedule proposal then separate server-side confirmation endpoint, idempotency and overlap checks; direct writes are disabled.
- Memory proposal/confirm, list and delete scaffold.
- Insight/trend scaffolds grounded in observations.
- Optional Anthropic SDK adapter, disabled by default.
- Report intake validates file signature, stores files under a digest-named per-user directory, and supports optional GPT-4o extraction plus user-scoped original-file retrieval. Directory hashing is path hygiene, not encryption; secure object storage/retention remain required for production.
- Formula review proposals are versioned and queued as `PENDING_REVIEW`; proposals are not executable and no reviewer approval/activation endpoint is enabled.
- Predictive placeholders that do not forecast or send alerts.
- Video metadata registration; no video generation pipeline.
- 44 automated tests pass in the local development environment, including mocked GPT-4o OCR payload, candidate evidence, local-timezone baseline, report signature and sleep interval prototype tests.

## Explicitly incomplete

- Executable, domain-reviewed Rally formulas beyond the clearly labeled sleep interval and raw-median prototypes; calibrated confidence aggregation.
- OCR benchmark live-provider score, provider compatibility verification, protected report-file/object storage and reviewer UI.
- Lab-specific mapping approval; current OCR alias map is narrow and not medically reviewed.
- Questionnaire instruments, validated scoring and sensor-fallback rules.
- Reviewer identity/authorization and controlled activation of reviewed formula implementations.
- Qualified approval of workout contraindications and health claims.
- Approved article corpus, RAG, citation validator and human-reviewed content workflow.
- Full LLM tool orchestration, prompt-injection red team, streaming, operations monitoring and incident workflow.
- Production privacy/legal review, retention/deletion, encryption/key management, rate limits, backups and latency/cost load tests.


## Current additional prototypes

- GPT-4o OCR adapter is off by default, requests verbatim transcription plus structured candidates, checks candidate quotes against the returned transcription and requires user confirmation. This does not establish that GPT's transcription is visually correct.
- ClinOCR-Bench v1.0 inventory is downloaded and verified (384 synthetic scans, paired ground truth, 328 test/56 exemplars). The benchmark runner supports CER/WER scoring.
- Sleep interval prototype unions overlapping asleep stages within a local-noon-to-noon window; it is explicitly non-reviewed and has no calibrated confidence or Rally sleep score.
- Baseline and raw-median grouping use profile/request timezone; confidence is marked heuristic/unavailable, not calibrated probability.

- Report review endpoint returns original-file URL; a dedicated browser/mobile review UI is still not implemented.

## Verification at this scaffold stage

- Observation ingest preserves provenance and normalizes supported units/timestamps; duplicate and conflict cases are explicit rather than silently merged.
- Baselines enforce distinct valid-day thresholds; default API minimum is 7 distinct days and remains configurable, not clinically validated.
- 44 automated tests pass in the local development environment, including mocked GPT-4o OCR payload, candidate evidence, local-timezone baseline, report signature and sleep interval prototype tests.
- These checks do not measure clinical/AI KPIs and do not establish production readiness.

## Production gates

Do not expose publicly or ingest real health data until per-user identity, consent, access control, storage protection, audit, retention/deletion and privacy review are complete. Do not release health advice, anomaly alerts or auto schedule changes until their rules are reviewed and independently evaluated.
